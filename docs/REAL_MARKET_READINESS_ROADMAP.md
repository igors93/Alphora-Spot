## How to use this roadmap

- Treat each work-item ID as a separate issue or pull request. Record an owner, target release, evidence link, and the result of its acceptance check. Do not close an item on implementation alone.
- **P0** blocks any real-money pilot; **P1** blocks a credible paper/testnet promotion or sustained live operation; **P2** improves maintainability and scale. Dependencies named in an item must be complete first.
- The bug backlog below contains observed defects and documentation errors. Later sections describe new capabilities, hardening, validation, and launch gates; they do not assert that every listed behavior is currently broken.
- Reassess the backlog after each exchange API change, incident, strategy change, or major dependency upgrade. Keep release evidence immutable and tied to a commit, configuration hash, data hash, and model hash.

## What exists today and what the evidence says

Alphora already has four execution modes, a Governor loop, exchange rules, pre-execution checks, protection-order logic, state reconciliation, portfolio risk checks, structured audit output, a backtesting engine, and a desktop interface. Relevant starting points are [execution modes](execution-modes-and-safety-guards.md), [the Governor](../src/governor/alphora_governor.py), [the Futures engine](../src/execution/engine.py), [the Binance client](../src/binance/futures_client.py), and [the backtesting guide](backtesting-engine.md). Build on these controls and prove their behavior under failure; avoid replacing them without a regression case.

The [2026-07-04 profitability audit](auditoria-lucratividade-2026-07-04.md) explicitly rejects the current strategy for real capital. Its chronological out-of-sample half had 24 trades, net PnL of -4.06, profit factor of 0.680, and expectancy of -0.169. The genuinely new window had zero trades. Its expectancy confidence interval crossed zero and every tested cost-stress scenario was negative. These are historical findings, not a fresh performance evaluation.

Local review checks on this baseline: `ruff check src tests` passed; `ruff format --check src tests` found one pre-existing unformatted test file; `mypy src` reported no issues in 328 source files, but [many high-risk modules are excluded from mypy errors](../pyproject.toml). `pytest tests -q --tb=short --ignore=tests/desktop` finished with **1,692 passed, 1 skipped, 1 failed**; a separate offscreen desktop run finished with **161 passed, 1 skipped**. The one test failure is an assertion that the installed Coalestra is `0.6.4`; both available local interpreters have `0.6.3`. This is **environment drift**, not evidence that the tested backtest logic is wrong. The suite must be rerun in an environment satisfying the declared dependencies. No exchange order or live-mode run was performed for this review.

## Phase 6 — promotion gates and controlled rollout

These are **proposed release gates**, not claims of current readiness. Keep the recorded evidence and operator sign-off for each transition. A failed gate sends the strategy back to the previous observation mode; it never authorizes a larger trade to “collect data faster.”

| Gate | Required evidence | Decision |
|---|---|---|
| **G0: offline → paper** | FND, EXE, and RSK P0 items complete; BUG-01/02/03/05 and BUG-09/10/11 fixed (done 2026-10-29) and BUG-15/17 fixed; data checks pass; `BACKTEST_OK` **and** `ROBUST_BACKTEST_OK` on a reserved out-of-sample period; the RES-04 criteria pass. | Authorize paper observation only, with simulated fills and no exchange mutations. |
| **G1: paper → testnet** | Fresh paper trades across the intended symbols/regimes; reconciled costs and no unexplained orders or protection gaps; operator runbooks rehearsed; strategy and risk thresholds still pass. Predeclare a sample target within the audit's suggested **30–100 genuinely new trades**, and collect more if the confidence interval remains inconclusive. | Authorize exchange testnet mutations with the exact release/config. |
| **G2: testnet → small real pilot** | Fault-injection and testnet drills pass; every P0 item is closed; live execution costs and latency are within the validated envelope; no unresolved P1 safety defect; independent review approves the strategy evidence, risk caps, key permissions, alerts, and emergency plan. | Time-boxed, explicitly approved small-size real run on a tightly limited symbol set. |
| **G3: small pilot → sustained/expanded real** | Reconciled real fills, risk, funding, and PnL; no unexplained exposure, duplicate orders, or unprotected intervals; edge remains positive after actual costs over a predeclared sample; incidents are resolved and reviewed. | Increase limits only through a new release approval and staged rollout. |

### Evidence package for every gate

- Release manifest and clean-install results; full CI run; preflight output.
- Immutable backtest/robustness reports and their input hashes; paper/testnet/real journals with reconciliation and cost comparisons.
- Risk-limit configuration and breach tests; fault-injection results; emergency drill record.
- Strategy decision document with sample size, confidence intervals, cost stress, drawdown, known limitations, reviewer, approval expiry, and rollback conditions.
